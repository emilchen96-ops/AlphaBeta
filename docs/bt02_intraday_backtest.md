# BT02-A 日线策略分钟级触发回测

BT02-A 在保留 BT01 可审计交易事实链的前提下，为日线策略增加分钟级确认与执行能力。
默认语义是：分钟 `T` 收盘后才能确认条件，最早在下一根真实存在的分钟 K 线开盘成交。
系统不会使用分钟 `T` 尚未结束时的数据，也不会为了补齐时间轴伪造午休、停牌或缺失 K 线。

## 支持范围

- 单只股票、自选组合和全部 A 股的独立回测；
- 1 分钟触发，以及以已闭合 1 分钟线聚合的 5/15 分钟确认；
- `price_volume_breakout_sma_exit` 参考规则的安全日线候选日预筛；
- 未知或无法证明安全的策略自动退化为逐日分钟回放，不做可能漏信号的猜测性预筛；
- MiniQMT 本地日线与分钟线自动检查、按缺口补数、质量校验和 PostgreSQL 复用；
- 默认下一分钟开盘成交、信号分钟收盘成交（乐观研究模式）、次日开盘和信号日收盘限价兼容模式；
- A 股午休、停牌、涨跌停、高开限制、整手、资金、可卖持仓、成交量参与率、费用与滑点；
- 后台批量任务、取消、失败项重试、进程重启后的未完成任务认领；
- 分钟候选日、加载量、准备耗时、回放耗时、信号与实际成交的审计报告。

BT02-A 不支持 Tick、逐笔委托、Level-2、高频撮合或真实券商下单。组合与全 A 股任务是“每只
股票独立资金、独立账户、独立绩效”的横向比较，不是共享资金的投资组合净值。

## 分层处理流程

```text
策略与范围
  -> 校验/补齐 MiniQMT 本地日线
  -> 用截至候选日可知的日线事实做安全预筛
  -> 只校验/补齐买入候选日与数学上可能触发卖出的候选日 1 分钟线
  -> 分钟质量检查
  -> 按已闭合分钟构造当日部分日线
  -> 策略信号
  -> 风控 -> 订单 -> 模拟成交 -> 账本 -> 指标与审计
```

日线预筛分别计算买入与卖出候选日。买入候选日使用整日日线高点和成交量作为乐观包络；卖出
候选日把“当前价低于包含当前价的 N 日均线”严格化简为“当前价低于此前 N-1 日收盘均值”，
再用整日日线低点判断该日是否可能触发。只有这两类候选日进入分钟回放，持仓期间数学上不可能
触发退出的中性交易日会被跳过。预筛实现与不预筛的完整分钟扫描有等价性自动测试；策略没有
安全预筛器时，系统宁可多加载分钟线，也不会改变结果。

## 时间与未来数据边界

| 阶段 | 当时允许读取 | 禁止读取 | 最早成交 |
| --- | --- | --- | --- |
| 分钟 `T` 进行中 | 之前已闭合分钟 | `T` 的最终 OHLCV | 不成交 |
| 分钟 `T` 闭合 | 截至 `T` 的部分日线、历史日线 | `T` 之后分钟、当日最终日线 | 下一根真实分钟开盘 |
| 乐观研究模式 | 截至 `T` 的闭合数据 | 未来分钟 | `T` 收盘价 |
| 次日开盘兼容模式 | 完整信号日 | 下一交易日盘中未来数据 | 下一可交易日开盘 |

默认 `INTRADAY_NEXT_MINUTE` 在 09:30 分钟闭合后，最早使用 09:31 分钟的开盘；11:29
分钟闭合后，下一根真实分钟是 13:00；14:59 分钟闭合后当日没有下一根分钟，`DAY` 订单取消，
`GTC` 可等待下一可交易日。停牌不会通过向前填充价格伪造成交。

`INTRADAY_SIGNAL_CLOSE` 是明确标注的乐观研究模式，因为它假定在刚刚确认信号的同一分钟收盘
价可以成交。它适合比较策略上限，不应与默认可执行结果混为一谈。

## 数据准备与质量

浏览器正式回测统一使用 `MINIQMT` 来源。回测先查询 PostgreSQL 中已经同步的数据，只对真实
缺口发起补数，不重复下载已经存在且质量合格的交易日。日线阶段允许个股因停牌没有 K 线；
分钟阶段则要求候选交易日具备合法双交易时段、无重复时间戳、首尾分钟可解释，并与当日日线
OHLCV 保持允许误差内的一致。

候选日期即使相隔数周，也不会重新扩成一个连续区间。PostgreSQL 读取和 MiniQMT 补数使用同一
套稀疏日期分段：只合并相邻的实际交易日，并对相同请求做短期去重，避免后台 Worker 每次复检
都重复排队。批量 Worker 默认每 20 秒复检一次；批量页另行显示“分钟行情准备进度”，按已经
准备/需要准备的候选交易日计算，不再只能看到完成股票数为 0 的静止页面。

日线准备来源标记为 `BT02_A_DAILY_BACKTEST`，分钟准备来源标记为
`BT02_A_INTRADAY_BACKTEST`。数据提供方临时不可用时，后台任务延迟重试，不会立即形成忙循环。
批量任务关闭页面后继续运行；取消是协作式的，当前正在执行的单只股票会在边界处结束，但批次
保持 `CANCELLED` 且不会再认领新股票。失败或取消的股票可以单独重试。

## 报告与审计

单股报告除 BT01 的 Signal、RiskDecision、Order、Fill、Timeline 和 Integrity 外，还展示：

- 日线预筛候选日与排除日数量；
- 买入候选日、卖出候选日与分钟数据准备进度；
- 实际加载的分钟交易日和分钟 K 线数量；
- 数据准备、策略回放耗时；
- 信号确认时间、下单时间、尝试成交时间、成交时间与采用价格；
- 无成交原因和数据质量告警。

批量报告聚合候选日、分钟加载量、产生信号/成交的股票数量、失败原因、收益分布和回撤分布，
并提供 CSV 导出。取消和失败项重试通过持久化 API 操作，不依赖浏览器进程持续存活。
