# BT03-A 共享资金组合回测

## 目标与边界

BT03-A 在既有单股回测和“逐股独立回测”之外增加第三种语义：多只股票共享同一笔现金、
同一账户和同一时间轴。它回答“如果这组信号真实争用一笔资金，组合会怎样”，不是把若干
独立账户的收益率做平均。该能力仅为历史模拟，不连接券商、不发送真实订单。

三种模式必须明确区分：

| 模式 | 资金与持仓 | 报告用途 |
| --- | --- | --- |
| 单股回测 | 一只股票、一个账户 | 检查策略在单一标的上的信号与成交 |
| 逐股独立回测 | 每只股票各自拥有完整初始资金 | 横向比较样本，不代表可实现组合收益 |
| 共享资金组合回测 | 所有股票共用一笔现金和持仓上限 | 评估资金竞争、仓位占用和真实组合路径 |

## 组合执行规则

- 默认初始资金 100,000 元、单次目标仓位 20%、最多同时持有 5 只、组合最高仓位 100%、
  单只股票最高仓位 20%。这些值均保存到不可变配置快照。
- 默认禁止同一股票重复加仓；卖出后允许后续新信号重新买入。
- 所有标的按统一事件时间推进。同一时间先处理卖出，再处理买入，使释放的现金可以参与
  当期后续买入。
- 多个买入信号竞争不足资金时，确定性排序为：信号强度降序、成交量比降序、证券代码升序。
  相同输入必须得到相同结果。
- 下单数量按组合权益目标仓位、单股上限、组合总仓位、可用现金、费用、价格和 100 股整手
  共同计算，不能超过任何一项约束。
- 继续复用 A 股 T+1、停牌、涨跌停、交易日历、费用、滑点和单次成交量参与率规则。无法成交
  的信号必须保留原因，不能静默消失。

## 分钟触发与性能

共享组合复用 BT02-A 的两层处理：先用日线安全条件排除不可能触发的日期，再只为候选标的和
候选交易日加载 MiniQMT 一分钟 K 线。日线安全排除只能减少分钟数据读取，不能改变策略结果。
批量任务由 Worker 持久化执行，允许关闭页面后继续运行，并保留取消、失败重试、恢复和 CSV
导出入口。

## API

创建仍使用 `POST /api/v1/research/backtest-batches`，其中
`execution_mode=SHARED_PORTFOLIO`。查询接口按用途拆分：

- `GET /api/v1/research/backtest-batches/{id}`：任务状态与总体进度；
- `GET .../{id}/preparation`：数据准备和分钟回放计数；
- `GET .../{id}/portfolio-report`：组合总报告；
- `GET .../{id}/equity`、`snapshots`：权益与估值快照；
- `GET .../{id}/orders`、`fills`、`trades`、`rejections`：事实和拒绝审计；
- `POST .../{id}/cancel`、`retry-failed`：控制与恢复；
- `GET .../{id}/export.csv`：可复核明细。

组合报告在运行尚未生成时返回明确的 `ready=false`/空结果，不伪造统计。
共享资金组合由批量任务预先完成股票范围校验，因此底层组合运行使用
`backtest_batch_max_instruments` 作为股票数量上限；普通单股/多标的直接回测仍使用较小的
`backtest_max_instruments` 保护上限。两种上限不得混用，否则合法的自选组合会在 Worker
执行阶段被错误拒绝。

## 报告解释

组合总报告优先展示累计收益率、基准累计收益、超额收益和最大回撤。权益图以 0% 为共同起点，
默认不显示账户金额，避免不同初始资金造成视觉误导；最大回撤区间用峰值、谷值和恢复点标记。
回撤图只显示 0% 及以下的历史回撤，并展示当前回撤、最大回撤、最长回撤期和恢复日。

报告同时包含：初始/期末权益、年化收益、Sharpe、成交数、胜率、盈亏比、平均持有期、平均
仓位、空闲现金、最大持股数、逐股已实现/未实现贡献、交易与成交明细、拒绝原因。逐股独立
模式保留收益分布以及“收益—最大回撤”散点图；散点图不应被解释为共享资金组合表现。
逐股贡献必须覆盖任务股票范围内的全部股票；已清仓或从未持仓的股票仍返回零值的当前市值、
未实现盈亏和总贡献，报告汇总与 CSV 导出不得因缺少期末持仓记录而失败。

回测快照中的总敞口是金额；组合报告展示资金使用率时必须除以同一快照的总权益，禁止把金额
直接格式化为百分比。

## 数据库与兼容性

`0033_bt03_shared_portfolio.py` 将批量回测范围约束扩展到 `MANUAL`。执行模式和组合规则保存在
`backtest_batches.configuration` 快照中，组合运行仍复用既有 BacktestRun、Signal、Order、Fill、
账本、权益和时间线事实，不建立第二套交易事实。旧记录缺少 `execution_mode` 时按
`INDEPENDENT` 读取，保证历史结果和旧入口继续可用。

共享组合失败或报告尚未生成时，网页必须根据批次执行模式显示稳定的失败/等待状态，并展示
可读失败原因；此时组合摘要不会包含逐股独立模式的 `counts`、`ratios` 等统计，前端不得读取
这些缺失字段或触发整页错误。

## 验收重点

1. 资金只够一个同刻买入时，排序第一的标的成交，其余产生明确拒绝原因。
2. 同一时刻卖出释放现金后，后续买入可以使用该现金。
3. 20% 目标仓位与 5 只上限不会突破组合 100% 和单股 20% 上限。
4. 同股默认不加仓；平仓后允许重新买入；T+1 禁止当日买入当日卖出。
5. 费用、滑点、整手、成交量上限、停牌和涨跌停均进入订单/成交/拒绝事实。
6. 组合权益恒等于现金加持仓市值；图表累计收益、基准和回撤可由快照重算。
7. 单股与逐股独立模式回归结果不因 BT03-A 改变。
