# CAL01-R 日历与智能选股窗口语义

CAL01-R 修复了智能选股把法定休市日当成普通开放日、把停牌和新股历史不足混成行情
Provider 失败的问题。此文档是该行为的封板口径。

## 核心不变量

1. A 股开放日来自版本化、可审计的交易所休市安排，不用工作日推测。
2. 法定节假日不是数据缺口，不请求 MiniQMT，也不伪造 K 线。
3. 已知停牌日不是数据缺口；逐股指标向前取真实有效 K 线。
4. 所有股票的市场事件条件共享同一日历窗口，停牌不会扩大某只股票的事件观察期。
5. 新股历史不足只跳过该股票，不阻塞全市场任务。
6. 只有 MiniQMT 明确返回失败才属于 `PROVIDER_FAILED`。
7. 大量股票集中缺少同一日期时优先诊断日历，而不是制造数千个重复下载请求。
8. 重试只补真实开放日缺口，保留旧任务和分类快照。
9. 选股任务按自身的 MiniQMT 补数批次跟踪进度；队列排空后保留短暂落库确认期，
   随即重新检查本地 K 线，不再机械等待最初的最长耗时估计。
10. MiniQMT 历史请求成功完成后，若已上市股票在指定开放日仍没有日线、但窗口内存在
    其他真实日线，则把该日期记录为可审计的推断停牌事实，不再循环下载；没有任何日线
    且缺少可信上市日期的标的归为参考资料不足。

## 2026-06-19 修复

2026-06-19 为端午节休市日。2026-06-18 的下一开放日是 2026-06-22，
2026-06-22 的上一开放日是 2026-06-18。以 2026-07-28 为截止日向前取 32 个
市场交易日时，窗口应从 2026-06-12 开始且不包含 2026-06-19。

## 分类与用户动作

| 分类 | 含义 | 是否补数 | 建议动作 |
| --- | --- | --- | --- |
| `READY` | 数据可计算 | 否 | 正常筛选 |
| `LISTING_HISTORY_TOO_SHORT` | 新股真实历史不足 | 否 | 等待积累交易历史 |
| `CURRENTLY_SUSPENDED` | 当前停牌 | 否 | 保留审计，不输出当日候选 |
| `STALE_DATA` | 长期无新行情 | 视原因 | 检查生命周期或行情源 |
| `DATA_GAP` | 真实开放日缺 K 线 | 是 | 增量补齐缺口 |
| `CALENDAR_MISMATCH` | 集中缺同一日期 | 否 | 修正并重同步日历 |
| `PROVIDER_FAILED` | MiniQMT 明确失败 | 可重试 | 检查 Agent 与 MiniQMT |
| `QUALITY_FAILED` | 重复或非法 OHLC | 否 | 修复数据质量 |
| `DELISTED` | 筛选日已经退市 | 否 | 不进入当日股票池 |

## 安全边界

本任务只读取 Instrument、交易日历、生命周期、停牌事实和 MiniQMT 历史行情；不读取
账户、资金、持仓、委托或成交，不创建 Signal、Order 或 Fill，不下单或撤单。
