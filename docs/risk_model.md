# 风险模型

风险控制分两层，任一层拒绝即订单不得执行。风险结果必须具备规则版本、输入摘要、理由、时间与审计关联。

## 第一层：后端风险控制

后端在 Signal 转为订单前实施策略、账户与组合级控制，包括：策略启停和版本许可、可交易标的、账户授权、单笔金额/数量、日内损失、持仓/行业/标的集中度、订单频率、重复意图、运行模式（模拟/只读/实盘）以及人工确认要求。只卖模式必须在此层阻止任何可能增加净多头或新开仓的指令。

## 第二层：Windows 执行器最终风控

执行器在调用 Broker 之前重新独立校验：设备授权、命令签名和有效期、幂等性、账户绑定、运行模式、人工确认凭据、白名单/黑名单、只卖模式、单笔与累计限额、订单价格/数量合理性、行情时效和 Broker 连接状态。执行器拥有拒绝异常订单的最终权力，即使后端曾允许。

## 运行控制与异常处置

- **紧急停止**：立即阻断新命令派发与执行；保留查询、审计和对账。恢复需显式授权和审计。
- **只卖模式**：仅允许降低既有可用仓位的动作；卖出数量不得超过可验证的可用数量。
- **标的名单**：白名单定义允许交易范围，黑名单优先于白名单；名单变更需审计和生效时间。
- **行情过期**：超过配置时效或质量不可信的行情不得用于新订单的价格/风险判断，应拒绝或进入人工处理。
- **Broker 断线**：停止新提交；取消、成交和状态不确定事项进入受控恢复/对账流程。
- **对账异常**：发现本地订单、成交、持仓与 Broker 事实不一致时，标记 `RECONCILIATION_REQUIRED`，冻结相关自动操作并保留差异证据。

AI 只能提供分析或 Signal，不能绕过两层风控、人工确认、订单状态机或执行器。
