# SC02-B 自然语言选股与可视化条件编辑器

SC02-B 把中文选股描述转换为 SC02-A 的受控 `ScreeningSpec`，再交给既有全 A 股
规则引擎运行。它没有新增第二套筛选计算器，也不会执行用户代码、创建研究信号、
订单或成交。

## 用户流程

1. 在“智能选股”输入中文描述并选择筛选日期。
2. 系统先使用本地确定性解析器匹配 `ConditionCatalog`。
3. 页面展示中文规则、默认解释、数据要求和数据就绪状态。
4. 用户通过 Schema 自动生成的中文表单确认或修改参数。
5. 每次修改都会调用预览接口重新校验并更新中文规则。
6. 点击“开始选股”后复用 SC02-A 创建接口、幂等保护、后台任务、进度和结果查询。

普通用户不会看到条件键、英文参数键、JSON、UUID 或幂等键。

## 解析优先级

```text
本地确定性解析
  -> 可选 AI 辅助
  -> ConditionCatalog 与参数 Schema 重新校验
  -> 用户可视化确认
```

本地解析器覆盖涨停回踩、底部放倍量以及标准目录中的常用价格、成交量、涨跌幅、
成交额和交易状态表达。支持阿拉伯数字、常见中文数字、百分比、倍数、万元/亿元、
历史日期、前 N 只和排序方向。

AI 只在本地结果为 `PARTIAL`、`AMBIGUOUS`，或看起来可由目录表达的
`UNSUPPORTED` 时尝试调用。AI 只能返回目录中已有的条件和合法参数；输出仍需通过
白名单、条件版本、参数范围、股票范围、日期和数据能力校验。AI 未配置或输出非法时，
系统保留本地结果并给出中文提示。

## 模糊与不支持表达

- “未明显跌破起涨价”默认解释为不低于起涨价的 98%，并在预览中明示。
- “明显缩量”默认解释为当前量不超过涨停日量的 50%，并在预览中明示。
- “找低位放量的股票”会返回待确认状态，并建议 60 日区间、底部 20%、20 日均量和
  2 倍成交量；用户确认或修改后才可执行。
- 暂无字段的基本面条件会返回“不支持”，不会被静默忽略。
- “或者”不会被悄悄改写成“并且”。

## API

- `POST /api/v1/screening-specs/parse`
- `POST /api/v1/screening-specs/validate`
- `POST /api/v1/screening-specs/preview`

解析返回 `COMPLETE`、`PARTIAL`、`AMBIGUOUS` 或 `UNSUPPORTED`，同时包含识别条件、
歧义、不支持片段、应用的默认解释、中文预览和可执行状态。所有错误沿用 API
Correlation ID；响应不包含 AI Prompt、Secret 或可执行代码。

## 安全边界

- 拒绝 Python、`eval`、`exec`、SQL、文件和 HTTP 调用描述。
- 拒绝未知条件、未知参数、过期条件版本、非法排序字段和越界值。
- 不接收客户端自定义计算器，不运行任意 JSON 逻辑。
- 只读取筛选日期及以前的本地 MiniQMT 历史日线。
- 不调用 MiniQMT 交易接口，不创建 Signal、Order 或 Fill。

## 当前边界

SC02-C 已在本能力之上补齐“我的选股方案”、不可变版本、历史结果、自选股和快速回测
预填接线。解析器和规则引擎仍是唯一的受控执行入口；再次运行必须先由用户确认，快速回测
也不会自动执行。盘中实时选股仍不在当前范围。
